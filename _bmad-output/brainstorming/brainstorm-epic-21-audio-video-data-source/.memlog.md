- (idea by user) Allow creating audio/video data sources where each data source can contain multiple files or links
- (decision by user) Create a dedicated YouTube data source (multi-URL) that extracts subtitles first and falls back to speech-to-text when subtitles are unavailable
- (idea by user) Define local audio/video data source(s) supporting multiple subtitle formats (SRT, VTT) with speech-to-text fallback when no subtitles exist
- (idea by user) Support source citations with audio/video timestamps on generated flashcards
- (idea by user) Support slicing each YouTube video or local audio/video file by timestamp into subdocuments
- (idea by coach) 3-tier transcript resolution waterfall for both local media and YouTube: (1) standalone or matching sidecar .srt/.vtt file / manual YouTube captions -> (2) embedded container subtitle track / YouTube auto-captions -> (3) Speech-to-Text fallback
- (idea by coach) Reuse already-configured provider keys (OpenAI Whisper / gpt-4o-mini-transcribe, Gemini native audio) alongside an optional local offline Whisper engine for STT fallback
- (idea by coach) For timestamp citations on YouTube flashcards, deep-link sourceOriginUrl with ?t=<seconds>s and format sourceLocator as [MM:SS - MM:SS] so clicking a citation jumps straight to that exact moment in the video
- (decision by user) Split local media into two distinct data source types: 'audio' and 'video' (alongside 'youtube', giving 3 media data source types total)
- (decision by user) Support OpenAI, Gemini, and local offline Whisper for Speech-to-Text (STT)
- (decision by user) When adding an item to an audio, video, or youtube data source, allow selecting the extraction method per item: specify/attach subtitles (.srt/.vtt) or choose which STT engine (OpenAI, Gemini, or Local Whisper) to use
- (idea by coach) Model per-item configuration in data source URI payload (uri/path, extractionMode: 'subtitles' | 'stt' | 'auto', optional subtitleFilePath for .srt/.vtt pairing, sttProvider: 'openai' | 'gemini' | 'whisper-local', and optional custom timestamp slices)
- (idea by coach) 3 timestamp slicing modes for youtube/audio/video items: (1) Custom Timestamp Ranges per item (e.g. 05:00-15:00, 15:00-30:00), (2) Fixed Time-Interval Blocks (e.g. slice every 10 or 15 minutes), and (3) Auto-Chapters / Full Transcript
- (idea by coach) Embed inline timestamp markers (e.g. [MM:SS] or [HH:MM:SS]) in extracted transcript text so the LLM populates Flashcard.sourceLocator with exact timestamps while GroundingGuard still verifies Flashcard.sourceQuote against the spoken words
- (decision by user) Support both custom start-end timestamp ranges per item AND automatic fixed N-minute interval / chapter slicing
- (decision by user) Trim/slice audio to custom timestamp ranges BEFORE running Speech-to-Text to save transcription time and API/compute cost
- (decision by user) Use inline timestamp cues in extracted transcripts so Flashcard.sourceLocator captures exact timestamps while sourceQuote holds verbatim spoken quotes
- (idea by coach) Subtitle cue coalescing & GroundingGuard timestamp normalization: merge fragmented 2-second SRT/VTT cues into natural sentence/time-window blocks and strip inline [MM:SS] markers inside GroundingGuard.normalizeText() so cross-cue verbatim quotes never fail verification
- (idea by coach) Task Center & Worker integration: stream step-by-step job logs during media sync (Subtitle probe -> Audio trim -> STT transcription progress -> Timestamp slicing) and show timestamp badges (start/end time) in SourceDocumentInspector and DocumentPreviewModal
- (idea by coach) Settings & CLI parity: add default STT provider and local Whisper model selection in SettingsView, plus CLI flags (--type youtube|audio|video, --stt-provider, --subtitles, --timestamps)
