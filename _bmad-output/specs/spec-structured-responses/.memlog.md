- (decision) Adopt In-House Native Provider Dialects driven by central Zod schema in core
- (capability) CAP-1: Provider-Native Structured Output Enforcement | intent: System generates flashcards using provider-native constrained decoding across all supported LLM providers without text-based JSON extraction. | success: 100% of generation calls across Gemini, OpenAI, Anthropic, and Ollama return valid objects conforming to the schema on the first pass without regex matching or fence stripping.
- (capability) CAP-2: Core Zod Schema Dialect Compilation | intent: System compiles a single declarative TypeScript/Zod card schema into provider-specific schema definitions and prompt guidance. | success: Modifying or adding a field in the core Zod schema automatically propagates to Gemini responseSchema, OpenAI json_schema, Anthropic tool schema, and Ollama format without modifying provider adapter code.
- (capability) CAP-3: Enriched Card Learning Facets | intent: System captures atomic keywords and exact document coordinates for every generated flashcard to support targeted recap drills and deep provenance navigation. | success: Every newly generated card persists an array of semantic keywords and a sourceLocator string, verifiable in the database and Question Explorer UI.
- (capability) CAP-4: Progressive Card Streaming and Truncation Retention | intent: System streams generated flashcards progressively as individual validated objects and commits all completed cards even if output token limits or interruptions occur. | success: In Task Center, generated cards appear incrementally via SSE during generation, and if a token limit cutoff occurs, all completed cards are preserved with a user warning notification.
- (capability) CAP-5: Elimination of Legacy String Sanitization | intent: System handles LLM responses with zero regex cleaners, markdown fence strippers, thinking tag removers, or syntax repair retry loops. | success: All legacy regex cleaners, sanitizers, and syntax-repair loops are removed from the adapters codebase and test suites pass with zero references to them.
- (constraint) Zero external runtime sidecars or microservices; all logic must reside within the existing TypeScript monorepo packages
- (constraint) Full multi-provider parity; all 4 active providers (Gemini, OpenAI, Anthropic, Ollama) must support structured generation
- (constraint) Database backward compatibility; existing flashcards in SQLite without keywords or sourceLocator must load without regression
- (direction) Non-goal: Automatic backfilling or LLM re-annotation of keywords/locators for historical cards
- (direction) Non-goal: Redesign of Generation Studio UI beyond displaying keywords, source locator, and partial warning badges
