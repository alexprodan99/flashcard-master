## 2. Findings (Aggregate Views & Cross-Story `bmad-review`)

### A. Cross-Story Correctness & Data Integrity Findings (Adversarial & Edge-Case Lenses)

1. **YouTube Backfill Stale-Snapshot Overwrite Race & Silent Error Swallowing (Critical)**
   - **Source:** `packages/core/src/services/ingestion-service.ts:139, 194-197, 441-509` (Story `22.3` ↔ `22.2` / `22.4`)
   - **Observation:** `syncSource` captures `source = sourceRepo.getById(sourceId)` at `:139` before `await strategy.fetch(...)` (`:194`). On completion, `backfillYouTubeSourceMetadata` parses that stale pre-fetch `source.uri` snapshot and writes `this.sourceRepo.update(source.id, { uri: serialized })` inside `try { ... } catch {}`. Any edit saved in another tab, CLI, or Desktop during ingestion/STT gets overwritten, and DB update failures are silently swallowed.
   - **Disposition:** **Fix now (Action Item 1)** — Re-fetch `latest = this.sourceRepo.getById(source.id)` right before writing, merge only missing titles/canonical URLs onto matching `videoId`s still in `latest`, and log non-not-found persistence failures.
   - **Upstream Lesson:** Long-running async pipelines must never persist mutations derived from pre-await entity snapshots.

2. **Cross-Process Active Job Clobbering & Unsynchronized Migration Under Unified `~/.flashcard-master/` Storage (Critical)**
   - **Source:** `packages/web/src/jobs/job-manager.ts:106-110`, `packages/core/src/storage/job-repository.ts:323-334`, `packages/core/src/storage/db.ts:119-135, 147-237`, `packages/cli/src/app.ts:95-118` (Story `22.1`)
   - **Observation:** Because Desktop and CLI/Web (`flashcard-master serve`) now share `~/.flashcard-master/data.sqlite`, starting a second server calls `JobManager` -> `jobRepo.recoverInterruptedJobs()`, which marks ALL `running`/`queued` jobs in SQLite as `'failed'` with zero PID/process ownership check—killing active jobs running in the first process. Additionally, `migrateLegacyDatabaseIfNeeded` uses a shared non-PID-unique `${actualCanonical}.tmp`, `hasUserData` ignores the `jobs` table on fast-path, and `createAppContext({ dbPath })` without `dataDir` splits `mediaDir`/`localFilesDir` back to `~/.flashcard-master/` while `inMemory: true` shares `os.tmpdir()/flashcard-master-inmemory`.
   - **Disposition:** **Fix now (Action Item 2)** — Add process lease/heartbeat scoping before marking jobs interrupted, isolate concurrent migration/`inMemory` temp paths, and derive sibling `mediaDir`/`localFilesDir` cleanly when `dbPath` is overridden.

3. **Notion Child Databases Permanently Freeze Edits in `new-only` Mode; Top-Level DB Query & Unchanged Parent Crawl Bugs (High)**
   - **Source:** `packages/adapters/src/ingestion/notion-strategy.ts:342-350, 452-474, 533-578, 621` (Story `22.2`)
   - **Observation:**
     - `crawlPageAndSubpages` (`:621`) calls `this.fetchDatabase(client, source, dbId, undefined, options)` with `lastSync = undefined`. Because `isPageUnchangedAndKnown` (`:466-473`) only overrides `knownMatcher` when `lastSync?.lastSyncedAt && pageLastEditedTime` shows `editedMs > syncedMs`, any already-known child database page is skipped forever in `'new-only'` mode even when edited.
     - Top-level `fetchDatabase` filters Notion queries with `last_edited_time: { after: lastSync.lastSyncedAt }` (`:343-350`), preventing re-ingestion of manually deleted DB rows (which are absent from `knownItemKeys`), leaving `skippedCount` at `0`, and advancing `lastSyncedAt` in `IngestionService` even after transient partial fetch failures (`rss`/`web`/`sitemap`/`llms-txt`/`notion` swallow errors).
     - Known unchanged recursive parent pages (`:533-578`) still call `renderPageBlocksToMarkdown` and download/WebP-compress embedded S3 images only to discard the parent document.
   - **Disposition:** **Fix now (Action Item 1)** — Forward `lastSync` cleanly into child database crawls, stop advancing `lastSyncedAt` or overwriting `itemCount` on failed fetches, and skip media downloads when inspecting unchanged known parent pages strictly for child links.

4. **Worker vs. Non-Worker (`IngestionService` vs. `task-worker.ts`) Split-Brain & Non-Transactional Full Purge (High)**
   - **Source:** `packages/web/src/workers/task-worker.ts:391-645`, `packages/web/src/workers/worker-executor.ts:166-176, 293-322`, `packages/core/src/services/ingestion-service.ts:235-248, 389-393` (Story `22.2` ↔ `22.4`)
   - **Observation:**
     - Only `source.type === 'local'` runs inside the worker thread; 8/9 source types execute on the HTTP main thread via custodial `COMMIT_SYNC_RESULT`.
     - For worker `local` syncs: `localStrategy.fetch` exceptions (`UnsupportedDocumentError`, `DrmProtectedEpubError`, `InvalidEpubError`) are caught at `task-worker.ts:427-438`, zeroed to `rawDocs = []`, and saved via `persistLocalSyncState(sourceId, 0)` as a warning/success; `totalFetched` is set to slice count (`msg.documents.length`) rather than `rawDocs.length`; `totalSteps` in `sync_all` is clobbered mid-run by local file count (`task-worker.ts:459-465`); `deleteBySourceId` in `'full'` mode is skipped if `msg.documents.length === 0`; and `lastGuid`/`contentHash` are never updated.
     - In `IngestionService.syncSource`, `'full'` re-syncs only run `deleteBySourceId` when `isSlicingActive || shouldResetToUnsliced` (`existingDocs.length > rawDocs.length`), so replacing URL/video/page items while keeping count `<=` leaks orphaned removed documents; neither path wraps `deleteBySourceId` + `upsertBatch` in a transaction.
   - **Disposition:** **Fix now (Action Items 1 & 2)**.

5. **Primary "Save & Sync" (`new-only`) Ignores Modified Slicing/Media Extraction Config on Already-Synced Items (High)**
   - **Source:** `packages/web/client/src/components/EditSourceModal.svelte:288-293`, `packages/core/src/services/ingestion-service.ts:177-180` (Story `22.4` ↔ `22.2`)
   - **Observation:** Editing `defaultSlicingMode`, `intervalMinutes`, `timestampRanges`, `sttProvider`, or `extractionMode` on already-synced items in `EditSourceModal` and clicking the primary **⚡ Save & Sync** button dispatches `syncMode: 'new-only'`, which matches by parent URI/`videoId` (stripping `#cfg=`) and skips re-processing the reconfigured items unless the user manually selects **Full Re-sync** from the dropdown.
   - **Disposition:** **Fix now (Action Item 4)** — Detect slicing/media-config changes in `EditSourceModal` (auto-selecting `'full'` for Save & Sync or prompting clearly when existing config changed).

6. **Duplication & Parity Drift Across `sync-item-keys.ts`, `formatters.ts`, `notion-strategy.ts`, `web-reader-strategy.ts`, and `server.ts` (High)**
   - **Source:** `packages/core/src/services/sync-item-keys.ts:10-158`, `packages/web/client/src/lib/formatters.ts:58-160, 336-520`, `packages/adapters/src/ingestion/notion-strategy.ts:70-75`, `packages/adapters/src/ingestion/local-file-strategy.ts:211-232`, `packages/web/src/server.ts:3871-3963` (Story `22.2` ↔ `22.4`)
   - **Observation:**
     - Client matching helpers in `formatters.ts` duplicate `sync-item-keys.ts` (`stripUrlFragment`, `extractYouTubeVideoId`, `normalizeLocalFilePathKey`, `extractNotionHexId`) and `parseMediaSourceItems`.
     - **EPUB fragment bug:** Both `stripUrlFragment` and `stripClientUrlFragment` fail to strip EPUB `#fragment` anchors containing spaces or non-HTML extensions (`a.epub#Chapter 1.xhtml`), causing repeated full EPUB re-ingestion in `new-only` mode.
     - **Notion `?p=` mismatch:** `NotionStrategy.extractNotionId` prioritizes `?p=pageHex32`, whereas `extractNotionHexId` & `extractClientNotionHexId` take the first 32-hex ID (DB ID).
     - **`audio`/`video` directories:** `MediaTranscriptResolver` expands directories into files and skips them, while `server.ts:3908` & `formatters.ts:509` restrict `dirPrefix` matching to `local`, always showing `'new'` on `audio`/`video` directories.
     - **Path trailing slash & POSIX Windows-casing parity:** `normalizeLocalFilePathKey` preserves trailing `/` and gates Windows lowercasing on `process.platform === "win32"`, while `normalizeClientLocalPathKey` strips `/` and always lowercases drive paths.
   - **Disposition:** **Fix now (Action Item 3)** — Extract a single browser-safe pure key/URI matching module shared across Core, Adapters, Web server, and Web client.

7. **Security & Resource Hardening on Local Web Server & Outbound Strategy Fetches (High)**
   - **Source:** `packages/web/src/server.ts:1704, 2780-2789, 3054-3118`, `packages/adapters/src/ingestion/sitemap-strategy.ts:46-87`, `web-reader-strategy.ts:236`, `llms-txt-strategy.ts:70`, `youtube-strategy.ts:210, 1035`
   - **Observation:** Open `Access-Control-Allow-Origin: *` exposes unauthenticated local endpoints (`/api/sources/youtube/resolve`, `/api/settings/*/test`) to cross-origin pages; `SitemapIngestionStrategy` follows `<loc>` URLs without scheme/private-IP checks; `response.text()` lacks byte caps; `POST /api/sources/upload` overwrites same-basename uploads inside `local-files/` and lacks trailing `path.sep` boundary enforcement.
   - **Disposition:** **Fix now (Action Items 2 & 3)** / track pre-existing deferred upload checks.
