## 3. Architectural Health & Invariants Check

1. **Hexagonal Architecture (AD-1, AD-4):**
   - Invariant strictly maintained: `packages/core` specifies the `LLMProviderPort` contract; all HTTP fetch endpoints, vendor APIs, and auth headers are strictly encapsulated inside `packages/adapters/src/llm/`.
2. **Mandatory Verbatim Citation Guard (FR-202, AD-5):**
   - Every generated card must carry an authentic `sourceQuote`. `GroundingGuard` rejects fabricated citations and trivial single-word quotes.
3. **Cognitive Customization & Calibrated Difficulty (FR-203, FR-204):**
   - Preserves 3 protected system personas while supporting custom user definitions. Difficulty modifiers adjust depth without violating the Minimum Information Principle.
4. **Atomic SQLite Persistence & Integrity (FR-205, NFR-302):**
   - `FlashcardRepository.createBatch()` operates inside SQLite `db.transaction()`, ensuring all-or-nothing consistency.
5. **Multi-Scale Deduplication (FR-206):**
   - `CardDeduplicationService` prevents both intra-batch and cross-sync duplicate card creation via token and character bigram metrics.

## 4. Key Learnings & Wins

- **Markdown Code Fence Stripping:** LLM providers frequently wrap JSON responses in markdown code fences (` ```json ` / ` ``` `) despite strict system instructions. Implementing a centralized `cleanJsonString()` utility in `types.ts` guaranteed parsing resilience across all 4 LLM adapters.
- **Combined Token & Bigram Similarity:** Relying solely on token Jaccard similarity occasionally misclassified short questions. Combining token Jaccard with character bigram Dice coefficient produced high-accuracy paraphrase detection while preserving distinct technical subtopics.
- **Zero-Telemetry Local Execution:** The entire persistence and fact-checking pipeline executes locally with zero third-party telemetry, adhering to privacy invariants (NFR-201, NFR-202).
