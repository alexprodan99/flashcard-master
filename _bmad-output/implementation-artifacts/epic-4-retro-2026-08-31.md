## 1. Epic Summary

Epic 4 delivered the comprehensive user interface and operator experience layer for Flashcard Master, unifying the local-first engine into a scriptable CLI suite, an interactive setup wizard, a native HTTP REST server, and a rich, embedded Single Page Application (SPA) dashboard with real-time sources management, interactive question exploration, inline card editing, and 1-click multi-format export centers with live AnkiConnect desktop badging.

### Stories Implemented (6/6 Done)

1. **Story 4.1:** Interactive Terminal Setup Wizard & Scriptable CLI (`createAppContext` dependency injection container, Commander.js CLI with `sync`, `generate`, `export`, `serve`, `stats`, and interactive first-run wizard in `packages/cli/src/`).
2. **Story 4.2:** Local Web UI Dashboard Server & Design System Foundation (`WebServer` in `packages/web/src/server.ts` with native HTTP REST endpoints `/api/health`, `/api/stats`, `/api/sources`, `/api/cards`, `/api/decks`, and responsive dark-theme Single Page Application).
3. **Story 4.3:** Sources Manager UI with Live Sync Status (`POST /api/sync/:id`, `POST /api/sync`, `PATCH /api/sources/:id` REST endpoints, interactive Sources Manager table, active status pills, modal add source form, and per-source/bulk sync triggers with spinner states).
4. **Story 4.4:** Question Explorer with Filter Chips & Visual Card Grid (substring search and tag aggregation in `FlashcardRepository`, `GET /api/tags`, and interactive Question Explorer tab with deck/difficulty/tag filter chips, responsive visual card grid, and click-to-reveal answers with verbatim source grounding callouts).
5. **Story 4.5:** Inline Card Editor Slide-Over Drawer (`GET/PATCH/DELETE /api/cards/:id` REST endpoints, animated slide-over drawer panel, multi-field card editor form, and optimistic UI update handlers).
6. **Story 4.6:** 1-Click Export Center & AnkiConnect Badging (`GET /api/export` file streaming with attachment headers for `.apkg`, `.csv`, `.tsv`, `.md`, and `.html`, non-blocking `GET /api/ankiconnect/status` health checks, `POST /api/ankiconnect/sync` desktop push sync, and scoped Export Center SPA view).

## 3. Architectural Health & Invariants Check

1. **Hexagonal Ports & Adapters Architecture (AD-1, AD-6):**
   - Maintained: The Web and CLI packages act purely as driving/inbound adapters communicating with core services (`IngestionService`, `CardGenerationService`, `ExportService`) through their defined interfaces and dependency injection containers.
2. **Local-First & Offline Privacy (NFR-201, NFR-202):**
   - Zero remote telemetry. The WebServer binds to `127.0.0.1` by default. AnkiConnect probing is entirely local and handles offline states gracefully without crashing or throwing unhandled errors.
3. **Grounding & Fact Verification Invariants (AD-5, FR-203):**
   - Verbatim grounding citations are surfaced throughout both the CLI inspection flows and the Web UI Question Explorer and Editor drawers.
4. **Resilient HTTP Server & Port Flexibility (AD-7):**
   - WebServer constructor supports ephemeral ports (`port: 0`) for test isolation and gracefully parses request body streams without hanging on empty requests.

## 4. Key Learnings & Wins

- **Self-Contained Embedded SPA:** Embedding the dark-mode Single Page Application directly within `packages/web/src/server.ts` allowed delivering a zero-install, zero-build-step frontend dashboard immediately accessible upon running `flashcard-master serve`.
- **Granular REST API & Optimistic UI:** Designing targeted REST endpoints (`/api/cards/:id`, `/api/sync/:id`, `/api/export`, `/api/ankiconnect/status`) enabled responsive UI interactions like filter chip toggling, inline slide-over drawer editing, and 1-click downloads.
- **Strict Vitest Test Isolation:** Using `describe.sequential` and dynamic port assignment (`port: 0`) ensured all 11 WebServer integration tests run reliably in CI and local test suites without port collision.
